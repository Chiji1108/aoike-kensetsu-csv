# 行政書士青池事務所 工事経歴CSV

顧客から受け取った工事経歴の Excel（列の構成は顧客ごとにバラバラ）を、許認可プロ①【建設業】.NET（株式会社クリックス、以下 建設業.NET）の
「CSV形式データインポート → 工事経歴データ」で取り込めるCSVに変換するWebアプリです。
公開URL：https://csv.aoike.jp

- ログインは事務所共通のパスワードのみ（ユーザー登録画面はありません）
- 顧客・年度ごとの案件に、届いたファイル（Excel・PDF）・記入用Excel・返ってきた Excel・出力した CSV と、画面の作業の状態を保存します（D1 と非公開の R2。消すのは職員が削除したときだけ）
- 変換は「確定できるものはコード（ルール）、判断が要るものだけ Claude」。AI の結果は必ず検算します

## 技術スタック

TanStack Start / React / TypeScript / Tailwind CSS v4 / shadcn/ui / Cloudflare Workers / Cloudflare D1 / Drizzle ORM / Better Auth / Zod / SheetJS / ExcelJS（記入用Excel） / encoding-japanese / @geolonia/normalize-japanese-addresses（住所の分割） / jsdiff（変更案の文字の差分） / Claude API（`@anthropic-ai/sdk`、モデル `claude-opus-5-5`） / Bun

住所データ：`public/japanese-addresses/api/ja.json` は [Geolonia 住所データ](https://github.com/geolonia/japanese-addresses-v2)（CC BY 4.0、出典: デジタル庁 アドレス・ベース・レジストリ ほか）の市区町村の一覧です。`bun scripts/update-addresses.ts` で最新にします（町字のデータは使わないので同梱しない）。

## 使い方

1. **顧客と案件**：顧客の一覧で顧客を作り、顧客の画面で年度の案件を作る。顧客の画面には顧客ルール、ヘッダーの「全体ルール」には全顧客に共通の決まりを書く（チャットの AI への指示に箇条書きで入る）。ルールは1項目1行の箇条書きで、項目ごとに直す・消す・並べ替え・足す（2つの画面で別の項目を直しても消し合わず、同じ項目を後から直すと食い違いを知らせる）。各項目に由来（職員・「2026年度の案件でチャットから」）を出す。全体ルールははじめ事務所のやり方の初期値が入っている。全体ルールの画面の「7割の計算」（税抜・税込）は新しい案件の初期値
   - 案件に届いたファイルを付ける（複数可。PDF も付けられ、チャットの AI に渡す。表になるファイルが無い PDF だけの案件は、チャットで AI に表を作らせる）。最初に付けた表のファイルが変換の元になり、一覧の「変換の元にする」で変えられる。千円未満の端数（切り捨て／四捨五入）・Excel の金額が税込か税抜か（分からなければ顧客に聞く）・7割の計算（決算書の完成工事高が税抜か税込か。初期値は全体ルールの画面の設定）を設定。2〜4択の設定はセグメントコントロール。CSV などのファイル名には顧客名を使う
   - 作業（列の対応・変換の AI の結果・手直し・置換・行の入れ外し・問い合わせ・取り込んだ回答・設定）は変わるたびに自動で保存し、開き直すと続きから。変換の行は保存せず、元のファイルと AI の結果から作り直す（AI は呼ばない）
   - 案件・顧客の削除は、消える案件とファイルの件数を見て顧客名を入れて確定する。D1 の行と R2 のファイルをすべて消す（途中で失敗しても、もう一度押せば消し切れる）
   - 画面は左に結果の表、右にチャット（1280px より狭い画面では、チャットは「チャット」のボタンで表に重ねて開く）。ファイルは表の欄にもチャット欄にも落とせる。この画面で書き出した最後の Excel（照合用の隠しシート）と記入用Excel は印で見分けて取り込み、ほかの表は届いたファイルにする（変換の元がもうあれば、変換の元にするか聞く）。照合用のシートの無い最後の形の表（見出しなし A〜N）は、変換の元がまだ無ければそのまま変換の元にし、あれば表に戻せないと伝えて変換の元にするかを聞く
2. **自動で変換**：ファイルを落とすと、AI（APIキーが無ければ見出しの語）が使うシート・見出しの行・元の表のどの列を14列のどれに使うか・どう変換するかを決め、そのまま変換する（ルールで変換し、決まらなかった値だけを AI に送る。値は重複を除き最大100件ずつ）。「変換する」のボタンと列の対応の表は無い
   - チャットの最初の返事（**変換の報告**）に、計画の AI のメモ（税込・税抜、注記のある行、不完全な日付、未成の工事など）、確かめる行の件数（押すと表を絞る）、聞き返し（Excel の金額は税込か税抜か）、去年との違いを出す。どの列を使ったかはチャットで聞けば答える
   - 列の対応を変えたいときはチャットで頼む（「金額は税込の列で」「工事名は B 列と C 列をつなげて」）。AI は `set_plan` で計画の差分を変更案にし、承認すると今の計画に重ねて変換し直す（手直しはその上に重なる）。差分は AI の計画の取り込みと同じ決まりで確かめる（項目の型に合う変換か、注文者・工事名・配置技術者は匿名化する変換だけで、注文者・工事名に定数は書けない、列がシートの中か）。使うシートはファイルの欄で選び直す
3. **プレビューと手直し**：表は、はじめは確かめる行（エラー・要確認・AI の推定・顧客への問い合わせが要るセルがある行）だけ。セルの色＝状態（青＝ルールで変換、紫＝AI、黄＝要確認、赤＝エラー）。セルをクリックして直接直せる
   - 表の上のボタンで「確かめる行」「問い合わせが要る」「AI の推定」「エラー」「要確認」「変更あり」（ルール・AIで変換、手直し、顧客の回答で変えたセル）のある行だけに絞れ、「すべて」で全行。請負代金の合計（切り捨て・四捨五入）、7割、問い合わせ、工事場所、一括置換は表の下の欄。見出しのクリックで並べ替え（表示だけ。CSV の順は変わらない）、「表示する列」で列を隠せる
   - 3,000行でも重くならないよう、表は見えている行だけを描く
   - **Excel で直す**：書き出した最後の Excel（7.）を Excel で直し、チャット欄か表の欄に上げると、落としたときの値との差分が変更案（チャットと同じ承認の画面。チャット欄の報告の下）になる
     - 値を直す → セルの変更案、行を消す → 載せない、行を足す → 工事を足して載せる。値は CSV の値（業種のコード・千円・YYYYMM・記号）のまま書き、取り込むときに変換と同じ決まった処理に通す。記号（Ａ・Ｂ…）はそのまま匿名化の値（落としたあとに記号が付け直されても同じ人）。注文者・工事名を実名に書き換えたら、変換と同じ匿名化に通す（確かめられなければ取り込まない）
     - 行は中身で見分ける（並べ替え・足す・消すをしてもよい）。14列のうち11列以上が同じで互いにいちばん近い行を同じ工事とし（数値の列の桁区切りは無視）、決めきれない行（似た行が2つ以上・4〜6列違う行）・読めない値・個人名を確かめられない値・落としたあとに表のその値が変わっていた値（職員の手直しを上書きしない）は取り込まずに一覧で出す。別の案件・変換の元を変える前に落とした Excel は読まない。同じ Excel を2回上げても二重にならず、却下した変更は出し直さない。N列より右の値は取り込まずに知らせる（「CSV で保存」すると CSV にも出る）。上げた Excel は案件のファイル（直したExcel）に残る
     - 載せない行を載せる側に戻すこと・実名を見ることは Excel ではできない（表かチャットで）
   - 既定で「業種ごとに、元請（官公庁・民間）→ 下請、それぞれ金額の大きい順」に並べ替え。業種ごとの元請合計と、何件で7割を超えるかを表示
   - **承認の取り消し**：承認した変更案（チャット・Excel・工事場所）は「承認を取り消す」で戻せる（直前のものでなくてもよい）。承認で変わった手直し・入れ外し・7割の設定・列の対応・足した行の前と後を案件の作業に残し、取り消すと「後」のままの値だけを戻す（承認のあとに職員や別の承認が変えた値は残して件数を知らせる）。記録は30件・200KB まで。ルールの項目と顧客の覚えた工事場所は外に書いたので戻らない（画面にそう出す）。取り消した変更案のコードは翌年の「去年のやり方で直す」に添えない
   - 7割の基準額：業種ごとに「完成工事高の合計（千円）」「うち元請（千円）」を入れる（損益計算書の完成工事高のうち当該業種の額、税抜）。空欄なら行の合計。
     比率は基準額に対して、7割の対象の行（除外した行を除く）から出す。除外した行を手動で載せたものは比率に入れず別に出す。行を使い切っても7割に届かないときは警告。載せる工事の選び方は「7割ルールで選ぶ（記入例どおり）」か「全件を載せる（7割以上なら件数は自由）」。全件は除外・手動で外した行以外を全部載せる（軽微の10件は「それより多くは載せなくてよい」上限なので、軽微な工事も全部。顧客がすでに7割で絞ったデータもこちら）。チャットの AI も切り替えられる
4. **顧客に問い合わせる**：CSV に載せる行のうち、書類に要る項目（定義表の `required` か `filing`）が空のセルと、AI が自信なしとした工事場所の推定と配置技術者の姓と名の区切り（記入用Excelのセルに「推定です。正しいか確認し、違えば書き直してください」「推定です。姓と名の区切りを確認してください」を添える）。税区分が「不明」なら税込・税抜も聞く。元データに値があるのに AI を使えず空になった欄は聞かない（職員が変換をやり直す）
   - 区切りの無い氏名は、同じファイル（案件）に空白で区切った同じ氏名があればその区切りに合わせ（AI に送らない）、無ければ AI。顧客の回答の配置技術者も同じ手順を通す
   - 聞かなくてよいものはチェックで外す。メールの件名と本文をコピーし、記入用Excel（`記入のお願い_<顧客名>_<YYYYMMDD>.xlsx`、記入してほしい欄だけ色付き。行ごとの質問は「ご質問」の欄）を添付して送る（ツールからは送らない）
   - 質問の文: 問い合わせの欄を開くと、チャットに「AI で文面を作る」が出る（チャットで「問い合わせの文面を作って」と頼んでも同じ）。AI は今の問い合わせ（`get_inquiries`）を読み、顧客に伝わる質問の文（例「この工事は引渡日を完成日としてよいですか。」）を書き、同じ聞き方でよいものはまとめ、メールの件名と前置きも付ける（`propose_inquiry`）。変更案を承認した文だけを使い、承認は取り消せる。個人名・表の記号・ほかの顧客の名前が入った文は受け取らない。費用は案件に足す
   - 文の無い問い合わせ（AI を使えない・まだ作っていない）は決まった文（同じ欄・同じ理由で1つ。例「資料に配置技術者が見当たりませんでした。ご記入ください。」）。欄の質問の文・件名・前置きは職員が直せる（空にすると決まった文に戻る）
   - 返ってきた Excel を取り込むと、管理番号（行の key）で行を探して「顧客の回答」として反映。何を聞いたかは各行の照合用の列（隠し列）から読む
   - 推定の値がそのまま返ってきた欄は「顧客が確認」として推定の印を外す。工事場所の欄で聞いていない側（都道府県など）が書き換えられていたら、それも反映して一覧で知らせる
   - 注文者・工事名の記入は元データと同じ変換（個人名は AI で「Ａ」等）に通す。セルには記号ではなく人を持ち、記号は手直しまで当てて CSV に書く行から、CSV の順に Ａ から欠けなく付けるので、同じ人は案件のどこでも同じ記号になる（CSV に載せない行にだけいる人は、画面では「〔未掲載１〕」の形で出す）。AI を使えなかった記入は元データと同じく個人名の判定ができないものとして反映せず、一覧に出す（職員が見て手で入れる）。記入用Excelは顧客に返すものなので、個人名は記号ではなく氏名で出す（記号は CSV と画面だけ）
   - 空欄のまま・送付後に値が変わった欄・読めない記入（市区町村が読めない工事場所など）・照合用の列が壊れた行・知らない管理番号・2つ以上の行にある管理番号は一覧に出し、反映しない。取り込みの AI を待つ間にセルの値が変わったら（手直し・置換・変換のやり直し）、その回答も反映しない。工事場所は都道府県と場所名を一緒に反映し、片方を反映できなければもう片方も反映しない
   - ダウンロードした記入用Excelと、取り込んだ返ってきた Excel は案件のファイルに残る
   - 色付きの欄の外（右に足した列・メモ・別のシート）に記入があるか、読めない記入・照合用の列が壊れた行があり、まだ答えの無い問い合わせが残れば、チャットに「AI で読む」が出る。押すと AI がそのファイルを読み、残りの答えを変更案にする（決まった欄は先に読んだまま。AI はそこで読めなかった部分だけ）
   - 顧客がメールの本文で答えたときはチャットに貼る。別の Excel・PDF・Word・保存したメール（.txt・.eml）で届いたときはファイルを付けて、チャットで「回答を取り込んで」と頼む。AI は今の問い合わせ（`get_inquiries`）を読んで、どの工事のどの項目への答えかを決め（`record_answers`）、決めきれない答え（2つの工事に当てはまるなど）は職員に聞き返す。答えは記入用Excelの記入と同じ決まりで値にする（年月・工事場所の分け方・配置技術者の区切り・注文者と工事名の匿名化・検査）。変更案の項目には「（顧客の回答）」「（顧客が確認）」と添える
5. **チャット**（表の横）：職員がチャットで指示し、AI（`claude-opus-5-5`）がコード実行で案件の届いたファイルと今の表を読んで、直した案を**変更案**として返す。承認したものだけが表に入る
   - 変更案はセルの値・顧客への問い合わせ・行の入れ外し・工事を足す・7割の設定・列の対応・ルールの項目。「CSV を出して」「問い合わせの Excel が欲しい」などには、返事に決まった処理を始めるボタンを付ける（`offer_action`。書き出す前の確認・問い合わせの欄）。セルの値はどの文字が変わったかを色分けする。AI が足した行（PDF から作った行など）は全部のセルを要確認（黄）にする。「一覧で確かめる」で今の値と承認したあとの値を並べ、項目ごとに承認・却下できる。まとめて承認・却下もできる
   - AI が聞き返したとき（「これでよいですか」）は黄色の欄で出し、答えるまで承認できない。「いいえ」なら全部を却下する。変更案の無い聞き返しは、答えを AI に送って続けさせる
   - 「顧客ルールに追加して」と言えば項目の案（1つの決まりを1項目）が出て、承認で顧客ルール（または全体ルール）の末尾に項目として足す（同じ項目は二度足さない）。全体ルールと顧客ルールは毎回 AI への指示に入る
   - 承認した手直しの出どころは「チャット（承認）」。個人名は表では「〔Ａ〕」の形で AI に見せ、AI の値も同じ形で読む（記号が付け直されても同じ人）
   - 会話は案件に保存し、開き直すと続きから。「会話を終える」と、AI に渡したファイル（Files API とコード実行が作ったファイル）を消し、次の指示から新しい会話になる。案件・顧客を消すときも先に消す
   - 返事ごとの費用、案件の合計（変換の AI の分も含む）、顧客の年度ごとの合計を出す。費用はドルで保存し、円は見せるときだけ換算する。レートは Frankfurter（欧州中央銀行の参照レート、キー不要）からサーバーで取り、1日持つ。円の横にレートの日付を出す。取れないときはドルだけ出す。案件が10ドルを超えたら注意を出す（止めない）。1回の指示で道具を呼べるのは20回まで（コード実行は数えない）
   - **2年目以降**：同じ顧客の前の年度の案件があれば、去年の元の Excel と今年の元の Excel のシート構成・見出し・列の並びを決まった処理で比べ、違い（増えた・無くなったシート、足された・無くなった列、名前が変わった列、並びが変わった列）を変換の報告に出し、チャットの AI にも伝える。名前が変わった列は、見出しの名前が近い・値の文字の傾向がはっきり近い・同じ位置にある、のどれかで推定する
   - チャットの「去年のやり方で直す」で「顧客ルールどおりに表を直して」を送り、顧客ルールと、去年のチャットで AI が書いて職員が承認した変更につながったコードを参考に添える（そのまま実行はしない。今年の形に合わせて書き直させる）。コードは去年の案件の会話と変更案の状態からそのつど取り出し、去年の案件で分かっている個人名は〔個人名〕に置き換える。去年の案件を消すとコードも無くなる。コードが無ければ顧客ルールだけで直す
6. **工事場所を調べる**（表の下の欄、変換の報告のボタン）：CSV に載せる行のうち、都道府県が空か、AI の推定に自信の無い行の現場を、工事名と注文者でまとめて（重複を除いて）調べる
   - 調べ方は、顧客の覚えた結果（前の年度に職員が承認した結果）→ AI の知識（変換の所在地の推定と同じ AI。変換で推定済みの現場は飛ばす）→ Web 検索（Claude API の `web_search_20260209`、1現場3回まで）の順。知識は自信ありで住所データで検算できたものだけ使い、残りを検索する。検索はチャットとは別のやり取りで、結果をチャットの履歴に積まない
   - 始める前に現場の数・覚えた結果の数・費用の目安を出し、職員が「調べ始める」を押す（勝手に課金しない）。1回に100現場まで。裏の処理は Cloudflare Workflows で、画面を閉じても続き、進み具合（30件中12件など）を数秒ごとに出す。失敗した検索は自動でやり直し、それでも駄目な現場は問い合わせに回す。「止める」と残りは調べず、調べ終えた分で変更案を出す
   - 結果は変更案（同じ現場の行をまとめて1件）。承認すると都道府県・場所名が要確認（黄色）で入り、根拠の URL を添える。AI が自信なしとした結果は顧客に確かめる印も付く。見つからない現場・個人名のある現場（外に送らない）は顧客への問い合わせ。費用（Web 検索の料金 1,000回 $10 を含む）は案件の費用に足す
   - 承認した結果は顧客ごとに覚え（D1 の `csv_location_memory`）、翌年は検索せずに使う（要確認のまま出す。工事名と注文者が同じでも別の現場のことがあるため）。案件を消しても残り、顧客を消すと消える
   - チャットで「この現場ってどこ？」と聞けば1件だけ調べて変更案にし、「場所が空いている行を調べて」と言えば件数と目安を返して「調べ始める」を出す
7. **書き出す**：「書き出す」（チャットの「CSV を出して」でも）で、書き出す前の確認を1枚出す。載せる件数・7割に届いたか・業種ごとの完成工事高と元請の額・エラーと要確認の残り・Shift_JIS で書けない文字（Excel の「CSV で保存」では黙って「?」になる）を出し、決算書の業種ごとの完成工事高（7割の基準額と同じ値）を入れると表の合計と照らす（合わなくても止めない）
   - 出すのは主に **Excel**（`工事経歴書_<顧客名>_<YYYYMMDD>.xlsx`）。職員がこれまで作っていた形（シート1枚・A〜N の14列・見出しの行なし・1行目からデータ。業種・元請下請・JV・請負代金・PC等の額・主任・監理は数値、ほかは文字列）で、値は CSV と同じ（匿名化のあと）。Excel で開いて確かめ、「CSV で保存」して取り込む。照合用の隠しシート（案件・行の key・落としたときの値・記号の人のハッシュ。個人名もハッシュの鍵も書かない。鍵はサーバーが案件ごとに決め、隠しシートには鍵の印だけを書く）を持ち、直して上げ直すと表に戻る（3. の「Excel で直す」）。「CSV で保存」は開いているシートだけを書くので、隠しシートは CSV に入らない
   - 確認のボタンは「Excel」と「CSV」。CSV（`工事経歴書_<顧客名>_<YYYYMMDD>.csv`、CP932）は控え。落としたファイルは案件のファイルに残る

建設業.NET の取込は**追加**です（上書きではない）。同じCSVを2回取り込むと工事が重複します。CSV には見出し行がないので、取込画面の「1行目が項目行」の**チェックを外して**ください。

### APIキーが無いとき

`ANTHROPIC_API_KEY` が未設定でも動きます。列の対応は見出しの語から推定し、AI が必要な値（空白の無い氏名、都道府県の無い住所など）は
「APIキー未設定」の警告つきで元の値のまま残すので、プレビューで直接直してください。個人名かもしれない注文者・工事名は、個人名を CSV に出さないよう空のエラーにします（手で入力してください）。

### 実例での照合（`scripts/eval.ts`）

顧客の実データ（`sample/`、git の管理外）を、チャットなし・チャットで指示・顧客ルールあり指示1回の3通りで CSV にし、職員が作った CSV と列ごとに比べます。
案件定義（実データのパス・顧客名・職員の誤り・指示）と結果は顧客の情報を含むので、リポジトリの外に置きます。1回の照合の費用が5ドルを超えたら止めます。

```bash
EVAL_CASES=/path/to/cases.json EVAL_OUT=/path/to/out bun scripts/eval.ts <case> baseline   # チャットなし
EVAL_CASES=... EVAL_OUT=... bun scripts/eval.ts <case> edit    # 案件定義の指示を順に（変更案はすべて承認したものとして重ねる）
EVAL_CASES=... EVAL_OUT=... bun scripts/eval.ts <case> rules   # edit で出た顧客ルールを入れて「顧客ルールどおりに表を直して」の1回
EVAL_LOCATION_LIMIT=50 EVAL_CASES=... EVAL_OUT=... bun scripts/eval.ts <case> location   # 工事場所の調査（覚えた結果は EVAL_OUT に残り、2回目は使う）
EVAL_CASES=fixtures/eval/cases.json EVAL_OUT=... bun scripts/eval.ts synth-answers-mail answers   # 顧客の回答（聞いたセルの答えが正しいか・抜け・余計を数える）
EVAL_CASES=... EVAL_OUT=... bun scripts/eval.ts <case> inquiry   # 問い合わせの文面（AI の文で聞く数・まとめた質問の数、個人名・工事名・ほかの顧客名・決まった言葉が文に入っていないか）
EVAL_CASES=... EVAL_OUT=/path/to/run1 bun scripts/eval-run.ts      # 案件定義の variants をまとめて1回分（回ごとに新しい EVAL_OUT。1回の費用が EVAL_RUN_BUDGET_USD〔既定12〕を超えたら止める）
bun scripts/eval-report.ts --cases <cases.json> --out /path/to/report /path/to/run1 /path/to/run2   # 回を並べた表（report.md・report.json。平均・最小〜最大・揺れの幅）
```

回のフォルダには、回ごとの要約（`summary-*.json`。終わったか・落ちた理由を持つ）と、使った時点で足す費用（`costs.jsonl`。落ちた照合の分も残る）が入ります。表の値は終わった回だけで出し、落ちた・止めた回は数と理由を出します。まとめ流しは、前の variant が落ちたらその案件の残りを流さず、落ちたら 1 で終わります。
案件定義は `variants`（流す順）と `files`（変換の元のほかに AI に渡すファイル）も書けます。合成の例（技術者一覧が別ファイル・PDF で届いた数件、顧客の回答をメールの本文・記入用Excelの別の列・一部だけで受け取る `synth-answers-*`）は `fixtures/eval/cases.json` にあり（`bun scripts/make-sample-eval.ts`・`bun scripts/make-sample-answers.ts` で作り直す）、実データの案件定義と1つのファイルにまとめて使います。
照合は一致率を上げる目標ではなく安全網です。コードを簡単にしたときは、案件ごとのセルの一致率の下がり幅が2ポイント以内なら簡単な方を選びます（同じ条件で2回流した揺れは案件ごとに最大0.5ポイント。列ごとの一致率は揺れが大きいので比べに使わない。1.5〜2ポイントの境目なら両方を2回ずつ流して平均で比べる）。

## 建設業.NET 工事経歴データCSVの仕様

出典：公式雛形 `fixtures/工事経歴書(LF).csv`、手順書 https://clicks2.sakura.ne.jp/download/apply10/csvmanual.pdf 、
バージョンアップ履歴 https://clicks2.sakura.ne.jp/202301apply10verup/apply10updatehistory.html

- 出力は、最新の建設業.NET で取り込めた実績のあるファイルと同じ形にする（公式雛形の形では取り込み結果が空になった）
- 文字コード CP932（Shift_JIS）、BOMなし。改行は CRLF（末尾も）
- **見出し行なし**。雛形の見出しはセル内改行を含んで何行にもまたがり、「1行目が項目行」では読み飛ばしきれないため
- 値は囲まない。カンマ・改行・ダブルクォートを含むときだけ囲むが、取込が囲みに対応しているか分からないので検証で警告する（改行はエラー）
- 主任技術者・監理技術者はちょうど一方が 1（両方無ければ主任技術者 1・監理技術者 0、片方だけあればもう片方はその逆。両方 0・両方 1 は警告）
- 14列（順序固定）。列ごとの必須・値の型・説明は `src/lib/spec/koji-keireki.ts` の定義表を参照

## 設計メモ

### 仕様は1つの定義表に

`src/lib/spec/koji-keireki.ts` の `FieldSpec[]`（列記号・雛形の見出しそのもの・必須・値の型・欠落時の値）から、
検証・画面の列一覧・AIへのプロンプトの列説明をすべて作ります。列ごとの if 文はありません。
見出しから列を推定する手がかり（`KOJI_COLUMN_HINTS`）も同じファイルにあります。
将来「個人情報」「会社情報」のCSVを足すときは、この形の定義表を1つ追加します（雛形は Clicks の csvtemplate にあります）。

### 変換の登録表

`src/lib/convert/transforms.ts` の `TRANSFORMS` が `TransformId` → `{ label, kind: "rule" | "ai", accepts, run, ai }`。
`run` がルールで値を決め、決まらないときは `ai` の判断（`src/lib/convert/ai-tasks.ts`）に回します。
AI の結果は `ai.apply` が検算します。

- 氏名の区切り：空白を除けば元の氏名と一致すること
- 住所の分割：都道府県＋市区町村＋残り＝元の住所（都道府県を補ったときは 市区町村＋残り＝元の住所。セルは黄色で「補完」と表示）。
  AI に送る前に、住所データ（`src/lib/convert/address.ts`）で市区町村を引く。都道府県は住所に書いてあるときだけ取り、市区町村は1つに決まるときだけ取る（政令市の名前を省いた区は、県内でその区を持つ政令市が1つのときだけ）。決まらない住所だけを AI に送る
- 業種コード・年月：コード表・YYYYMM の形であること

検算に通らなければエラーにして元の値を残します。AI が `needsReview: true` を返したら要確認（黄）。

### 処理の流れ

1. 読込（ブラウザ、`workbook.ts`）：SheetJS でシートを `SheetGrid`（セルは表示値、日付は `YYYY-MM-DD`、結合セルは左上の値）に
2. 計画（`plan.ts` / `heuristic-plan.ts` / `server/ai.ts`）：ブックのシート（見出しが工事の項目にあてはまる3枚は先頭30行・末尾10行と列ごとの値の例、ほかは見出しらしい行のまわりだけ。職員がシートを指定したら、そのシートと見出しが同じシートだけ）と、シートどうしのデータの行の重なりを Claude に送り、使うシート（抜粋で振った番号）・見出しの行・列の対応（`MappingPlan`）を構造化出力で受け取る。zod で検証し、送っていない・空のシートを選んだら計画全体を、見出しの違うシート・写しのシートは外し、範囲外の列や型に合わない変換は選んだシートについての見出しからの推定に戻す。AI が使えないときだけ、見出しが工事の項目にあてはまるシート1枚で推定する
3. 変換（`convert.ts` / `pipeline.ts`）：行ごとに `RowResult = { sourceRow, cells: Record<FieldId, CellResult> }`。AI の結果はブラウザのメモリにキャッシュし、手直しや並べ替えでは再送しない
4. 検証（`validate.ts`）：値の型ごとの検証、必須、CP932 で表せない文字、字数の上限（注文者27字・工事名51字、半角は0.5字）、個人名が残っていそうな値（警告）、行の検証（J ≤ I、K ≤ L）
5. 出力（`csv.ts`）：encoding-japanese で CP932、CRLF、見出し行なし

6. チャット（`lib/chat/turn.ts` / `server/chat.ts`）：AI SDK（`ai`・`@ai-sdk/anthropic`）の streamText。AI はコード実行（`code_execution_20260120`）で案件のファイル（Files API に上げてコンテナに渡す）と今の表を読み、表の変更はコードから呼ぶ道具（programmatic tool calling）で変更案に溜める。表を作り直すのは画面と同じ `lib/cases/view.ts` の `deriveTable`

変換・検証・CSV出力・変更案は純粋関数（`src/lib/` 以下。React / Workers に依存しない）。Claude の呼び出しはサーバー関数 `src/server/ai.ts`、チャットの `src/server/chat.ts`、工事場所の調査の `src/server/location.ts`・`src/server/location-workflow.ts` だけです（モデルは `src/lib/constants.ts` の `MODEL`）。

### Claude API

- モデル `claude-opus-5-5`、構造化出力（`output_config.format` に zod スキーマ）。計画は effort `high`、値の判断は `medium`
- システムプロンプトは定義表と登録表だけから作るので毎回同じ文字列になり、プロンプトキャッシュが効く
- 拒否（refusal）のときは server-side fallback（`fallbacks: "default"`）で既定のモデルが引き継ぐ
- 送るのは計画時は各シートの先頭・末尾の数十行、変換時は重複を除いた値だけ。顧客の表をまるごと送ることはしない
- チャットでは案件の届いたファイルを Files API に上げ、コード実行のコンテナに渡す（コンテナは Anthropic 側に最大30日残る）。Files API のファイルは「会話を終える」と案件の削除で消す。会話の履歴がファイルを指しているので、消すまでは残る
- チャットの会話は R2 の `cases/<caseId>/chat.json`。AI に送る履歴は足すだけで前の部分は変えない（考えたことのブロックは履歴が変わると読めなくなる）。キャッシュの区切りは最後の文章かコード実行のブロックに付ける（コードから呼んだ道具の呼び出し・結果には付けられない）
- 費用は claude-opus-5-5 の料金（入力 $4・出力 $20・キャッシュ書き込み $5・読み込み $0.20、100万トークンあたり）で数える目安。コード実行のコンテナの時間の料金は入れていない

### 認証

- Better Auth の Email & Password を使用。メールアドレスは `src/lib/constants.ts` の `OFFICE_ACCOUNT_EMAIL` に固定し、ログイン画面ではパスワードのみ入力
- `disableSignUp: true` で公開登録を無効化。アカウントは `scripts/set-password.ts` で作成
- パスワードハッシュは Workers の CPU 制限を考慮し、Web Crypto ネイティブの PBKDF2-SHA256（100,000回）を使用（`src/lib/password.ts`）
- ログイン試行は D1 を使ったレート制限（1分間に5回まで）
- サーバー関数は同一オリジンからの呼び出しのみ許可（`src/start.ts` の CSRF ミドルウェア）。AI のサーバー関数はログイン必須
