# 工事経歴CSV チャット型への作り直し 計画

職員が顧客のExcelを読み込み、チャットでAIに直させ、差分を承認してCSVを作る形に作り直す。
土台は今の変換（列の対応・決まった変換）で、AIは Claude API のコード実行で表を直す。決まった処理は検査（業種コード・都道府県・字数・7割・個人名）とCSV書き出しに絞る。
全体ルールと顧客ルールを文章で持ち、2年目以降は顧客ルールを最初の指示にする。
PR は P1 から P6 の順。P1 と P2 は独立していて先に進められる。

## この計画の読み方

1つの箱が1つの作業で、箱ごとに確かめた証拠（テストの実行、ブラウザの画面、照合の一致率、コミット）を書く。
各PRは、単体テスト・ブラウザでの確認・実例での照合（該当するPR）の3つがそろって初めて確認済みとする。テストが通るだけでは確認済みにしない。
マージの前に `/code-review` を行う（ユーザーの全体ルール）。書類の正しさに関わる指摘は直してからマージし、整理だけの指摘は次のPRに回してよい。

poteto-mode の multi-phase-plan の雛形から変えた点（この規模の社内ツールに合わせた）:
- 1PRあたり10本の並行検証と1時間ごとの見回りは行わない。1PRにつき1人の担当が、ヘッドレスChromeでの確認と照合を行う。
- 顧客の実データは `sample/`（gitignore）にあり、照合の案件定義もリポジトリの外に置く。PR本文・コミット・テストに顧客名や実データを入れない。
